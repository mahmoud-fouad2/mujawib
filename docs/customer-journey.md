# رحلة العميل المُدارة

## 1. قبل الحساب

لا يوجد تسجيل ذاتي عام. تبدأ الشركة من العرض أو التواصل، ثم ينشئ فريق مُجاوِب
مساحة العميل ويحدد من سيصل إليها.

## 2. إنشاء مساحة العميل

يستخدم المشغّل `/onboarding` لإنشاء Workspace وبيانات النشاط ومسودة الموظف
الصوتي والخدمات والفروع ومسارات الربط. لا ينشر الـWizard نسخة حيّة تلقائيًا.

## 3. دعوة المستخدم

ينشئ Owner دعوة من `/console/access` لبريد ومساحة ودور محددين. الرمز أحادي
الاستخدام، صالح لسبعة أيام، ومحفوظ كـSHA-256 digest فقط. ينتقل في URL fragment
حتى لا يظهر في سجلات الطلبات.

صاحب البريد لديه مساران:

- حساب موجود: يسجل الدخول ثم يقبل الدعوة.
- حساب جديد: ينشئ الاسم وكلمة المرور داخل الدعوة؛ Server Action يتحقق من الرمز
  والبريد والدور ثم ينشئ الهوية وCredential وWorkspaceAccess وAudit Log معًا.

## 4. ما بعد الدخول

`/auth/continue` لا يفترض وجهة واحدة:

- دور تشغيل صالح يفتح `/console`.
- دور عميل صالح يفتح `/portal` لمساحته فقط.
- حساب بلا صلاحية يفتح `/access-pending`.
- لا يوجد اختيار لأول عميل ولا ترقية تلقائية إلى السوبر أدمن.

## 5. استعادة الدخول

طلب الاستعادة يعيد رسالة عامة لا تكشف وجود البريد. عند ضبط Resend يصل رابط
أحادي الاستخدام صالح لمدة ساعة. بعد تعيين كلمة مرور جديدة تُلغى الجلسات القديمة.

## 6. التشغيل

فريق مُجاوِب يراجع المعرفة والصوت والاختبارات والهاتف والتكاملات، ثم ينشر
AgentVersion اجتازت البوابات. العميل يرى النتائج والمكالمات والحجوزات وطلبات
التعديل، ولا يرى Prompt أو SIP أو الأسرار أو Tool schemas.
